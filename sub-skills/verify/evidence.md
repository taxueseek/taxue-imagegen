# 验收阈值实测依据

> 本文件是 `sub-skills/verify/` 全部阈值的**出处**。改任何阈值，必须同时更新这里。
> 纪律：答不出「在多少张什么图上实测、两组数据分别多少」的阈值，只能当诊断值，不许判 blocker。

## 1. 水印自动门：amp + R² 双条件

**样本**：2026-09-12，本机 `~/Pictures/WorkBuddy/` 真实产出 14 张（排除 `_reports` 与去水印产物）。

| 组别 | n | amp 区间 | k̂ 区间 | **R² 区间** |
|---|---:|---|---|---|
| 干净图 | 3 | −0.79 ~ −0.69 | −0.05 ~ −0.04 | **0.02 ~ 0.29** |
| 带水印图 | 11 | 1.62 ~ 45.48 | 0.90 ~ 1.40 | **0.76 ~ 0.96** |

**结论**：R² 是两组的真实分界（\|amp\| 单独用也能分，但 audit_wm 自己的文档就写明
「amp 高但 R² 低多半是高频纹理误报」，而纸纹/网点/格边正是本技能主力产出）。

**取值**：`AUTO_R2_THR = 0.50`，落两组之间且两侧留余量（0.29 与 0.76）。

**已知局限**：n=14，样本量不大。出现 0.29 < R² < 0.76 的图时走 `manual` 分支交人判断，
**不擅自扩大自动处理范围**。R² 区间一旦在真实产出上被证伪，优先收窄自动区而非放宽。

**amp 阈** `AUTO_AMP_THR = 1.0` 沿用 `audit_wm.AMP_CLEAN`，人眼可感阈 ≈1.5。

### 一处易被误读的实测

`poster_v3_clean_nw.png` 文件名含 `clean/nw`，实测却是 DIRTY（amp 6.91、R² 0.943）。
**这是文件命名与实际不符，不是检测假阳性**——R² 0.943 说明残差确实呈水印形状。
教训：判据以像素为准，不以文件名为准。

## 2. 类型 E 网格一致性

**样本**：2026-09-12，合成基准 5 张（3×3 / 4×4 / 2×4 一致网格 + 两个不一致用例）。

| 用例 | cells | cell_uniform |
|---|---:|---|
| 3×3 一致 | 9 | 1.000 |
| 4×4 一致 | 16 | 1.000 |
| 2×4 一致 | 8 | 1.000 |
| 某格窄 60px | 9 | **0.825** |
| 某格矮 30% | 9 | **0.700** |

**结论**：一致网格恒为 1.000，不一致落在 0.70–0.83。

**取值**：诊断线 `0.90`，**只报不拦**。理由：①这是合成基准，未在真实多格产出上重标；
②「无缝隙、边框像素对齐」是合法 E 变体，解析本就不稳。真实产出攒够样本后再决定是否升级为判据。

**格数是硬判据**（仅在给 `--expect-cells` 时）：`fill_meta` 已在 prompt 侧校验
「格数 = 清洁单条数」，图像侧再不符就是「说的和画的不是一回事」，属真错。

## 4. 2026-09-18 全库校准：判据在「已验收成品」上的触发率

**为什么要做**：postcheck 判 blocker 在评审卡里等于「允许一次定向重生」= 再扣 5–10 积分。
所以一条判据如果在本该通过的成品上频繁触发，它不是检测器，是**积分黑洞**。

**样本**：`~/Pictures/WorkBuddy/` 下 **202 张已归档成品**（排除 `_clean` / `_reports` /
`_textband`）——正样本＝你**留下来**的图。复算工具：`scripts/calibrate_thresholds.py`。

| 判据（改前口径） | 触发率 | 结论 |
|---|---:|---|
| `R-B ≥ 3` | **46.5%** | 退位：只在「本该是白」的子集里判 |
| `top_R-B ≥ 3` | **50.0%** | 与上一条是同一件事（留白偏暖），合并为一条 |
| `top_dev ≥ 12` | **64.9%** | 降为诊断：属风格张力，pitfalls 待解决表明写「不再重出」 |
| B · `white% ∉ [30,65]` | **82.2%** | 撤除：口径在纸底图上失效 |
| B · `sat > 70` | 3.0% | 保留为 blocker |

**分场景一测就分开**（`R-B ≥ 3` 按底色分组）：

| 分组 | n | `R-B ≥ 3` 占比 | `base` 中位 |
|---|---:|---:|---:|
| 纯白底（`white% > 30`） | 56 | **3.6%** | 244.0 |
| 纸底/纹理底 | 146 | **63.0%** | 164.0 |

结论：`R-B ≥ 3` 单独用时测的是「**有没有用纸底风格**」，不是「画得好不好」。
加上「本该是白」的门（`base ≥ 240`）后，命中 47/202 张、其中触发 **4.3%** —— 这才是可用的判据。

**取的新口径与理由**：

| 项 | 取值 | 依据 |
|---|---|---|
| `WHITE_BASE_MIN` | 240 | 扫 230/235/240/242/244：触发率 8.2% / 8.6% / **4.3%** / 2.5% / 0.0%。取 240：既压住假拦，又留住「本该是白」的样本量（47/202） |
| 白底泛黄的动作 | **pending + 指向 `paper_white.py`** | 坑 33 实测：同一提示词两版纸白都是 R-B +5.5，「三通道相等」写进硬底线也压不下来 → 重生**改不了**它，判 blocker 等于白扣积分 |
| `top_dev` / `top_zone%` | 仅诊断 | 触发 64.9%；且 4/9 风格里母题侵入顶部是设计结果 |
| B 留白占比 | 只提示（`near% < 40` 且 `base ≥ 200`） | 见下 |

**类型 B 的「挤成一团」为什么退出 blocker 位**（三个口径逐一证伪）：

1. 旧口径 `white%∈[30,65]`：`min(RGB)>240` 在纸底图上恒为 0（`measure.py` 2026-09-07
   已记录该缺陷），成品触发 **82.2%**。
2. 候选 `paper%<30`：`base` 取的是 `min(RGB)` 的**中位数**，按定义约一半像素 ≥ base，
   所以 `paper%` 恒 ≥ 50%（实测最小值 **50.2**）——这是**结构性死判据**，永远不会响。
   看着「0% 触发很干净」，其实是它根本不会说话。
3. 候选 `near%<40`：在 `base ≥ 200` 的子集（n=83）里仍占 12%，而本地**没有成体系的
   负样本**（真翻车的挤成一团图）来证明它抓的是「挤」而不是「画得满」→ 只做提示。

拦「挤成一团」的正手在 **prompt 侧**：类型 B 的可数约束（角色数量下限、最大角色 ≤ 画幅 1/4、
小角色 ≥ 1/12）已并入主模板；图像侧只给可测提示 + 目检。

## 6. 一条被反复验证的元纪律

本技能三次栽在同一类错误上，都是**假 blocker**：

1. 坑 27：`top_noise ≥ 6` 在 13/13 张真实海报上触发 → 每张都会触发一次定向重生
2. v1.13 开发中：自动水印把 `R²=0.00` 的格边残差判成「存疑」→ 干净格图被降级成 pending
3. 2026-09-18 全库校准：四条现役 blocker 在成品上触发 46.5% / 50.0% / 64.9% / 82.2%
   ——坑 27 当时只降级了 `top_noise` 一条，**同病的另外四条没被一起审**

共同点：**判据制造了不存在的缺陷，而 blocker 会直接扣积分**。
所以：

- 新判据一律先以诊断值上线，攒够真实样本再升级；升级时同时登记样本量与两组分布。
- **凡判 blocker，必须能回答**：在多少张已验收成品上触发过？复算命令是哪一条？
  答不出就走诊断，别走 blocker。复算入口：`python3 scripts/calibrate_thresholds.py`。
- 看到「触发率 0%」先别高兴：**确认判据本身会响**。`paper%<30` 就是反例——
  它按定义恒 ≥50%，永远不会触发。
